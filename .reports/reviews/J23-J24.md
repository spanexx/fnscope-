## Findings

- **F1 (blocker, J23)** `<py-wt>/crates/fnscope-parser/src/python/discover.rs:381` — helper is `fn node_text(node: &Node<'_>, source: &str) -> String`, but the call sites at `:223`, `:228`, `:232`, `:234`, `:240`, `:246`, `:262`, `:295`, `:296` pass `bytes: &[u8]` (declared at `:180`, `:217`, `:255`, `:273`). Rust does not coerce `&[u8]` to `&str`; each site is an E0308, so the Python adapter cannot compile. Required fix: normalize on one byte-slice helper (`fn node_text(node: &Node<'_>, bytes: &[u8]) -> String`) and change the three `&str` call sites at `:89`, `:147`, `:342` to `source.as_bytes()`, or convert the nine `bytes` sites to `&str`. Then let the orchestrator run the real gate; a rustfmt check is not evidence.
- **F2 (medium, J23)** `<py-wt>/docs/contract/adapters/python.md:51` — doc claims the `->` annotation defaults to `"void"`, but `<py-wt>/crates/fnscope-parser/src/python/discover.rs:260-269` stores an empty `type_` when no annotation exists (same as the Rust adapter at `crates/fnscope-parser/src/rust/discover.rs:255-265`). Required fix: correct the doc to "empty declared text, reported as `void` by the Return step" (`python/body.rs:238-245`), or change the adapter if `"void"` truly is the contract.
- **F3 (medium, J23)** `<py-wt>/tests/fixtures/python_app/README.md:58-62` (repeated at `<py-wt>/docs/contract/adapters/python.md:128-130`) — says core's default excludes drop `__pycache__/`, but `crates/fnscope-core/src/scan.rs:33-44` has no `__pycache__` pattern, and `:520-530` asserts the current list. Consequently the "at least 6 functions" expectation at `README.md:18` is wrong: a default scan would also find `generated_should_be_excluded` (`__pycache__/generated.py:4`). Required fix: registration job adds `**/__pycache__/**` to core's defaults (scan.rs:33-44 and the test at :520-530), or the fixture docs are corrected if exclusion is deliberately left to callers.
- **F4 (low, J23)** `<py-wt>/crates/fnscope-parser/src/python/body.rs:196` — `classify_statement(statement: Node<'_>, source: &str)` never uses `source`; the call at `:282` passes it anyway. This is an `unused_variables` warning (not a hard error). Required fix: remove the parameter and the `:282` argument.
- **F5 (blocker for registration, J23+J24)** `crates/fnscope-parser/src/adapter.rs:124` — `assert!(registry.for_extension("py").is_none());` will fail as soon as the Python adapter is registered. Required fix: replace `"py"` with a genuinely unregistered suffix (e.g. `"zig"`) or delete that assertion; also extend `builtin_registry_resolves_every_extension` at `:106-112` with `("py", "python")` and `("go", "go")`.
- **F6 (medium, registration)** `Cargo.toml:18-34` and `crates/fnscope-parser/Cargo.toml:8-15` — no `tree-sitter-python` or `tree-sitter-go` dependency; `Cargo.lock` has neither package. Cached 0.25.0 sources expose `pub const LANGUAGE`, so add `tree-sitter-python = "0.25"` and `tree-sitter-go = "0.25"` to workspace deps and `.workspace = true` entries to the parser crate.
