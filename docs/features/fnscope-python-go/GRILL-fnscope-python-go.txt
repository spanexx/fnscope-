DECISION 2 — Grammar wrapper nodes are the root cause of the nine test failures
------------------------------------------------------------------------------
LOCKED ANSWER [agent decision]
  Fix the AST walks, not the assertions, where the failure was a grammar
  wrapper node: unwrap `expression_statement` in Python discovery,
  `statement_list` in Go body analysis, and `field_declaration_list` in Go
  struct field indexing. Keep the fallback that uses the original node when no

DECISION 3 — Call vs Transform: spec section 4 step 3 beats a test expectation
-----------------------------------------------------------------------------
LOCKED ANSWER [agent decision]
  A variable/short declaration whose initializer invokes a function is a
  `call` step, not a `transform`. Where a test encoded `Transform`, change the
  test; where production also misclassified it, change both. Do not relax
  production to make the old expectation pass.

WHY
  The locked spec classifies `transform` as data work "without external
  calls", and its own schema example labels `const tokens = tokenize(...)`
  as `"kind": "call"`. One Go local doc line said `short_var_declaration`

SOURCE

DECISION 4 — Why reviewers failed first, then caught compile errors
-------------------------------------------------------------------
LOCKED ANSWER [agent decision]
  Treat a format or syntax check as evidence of formatting only. Reviewers
  report "PASS (source)" for a semantic read, never "compiles"; the
  orchestrator alone runs the compile gate. Every reviewer brief carries the
  L11 semantic-sanity item (truncated identifiers, wrong arity, undefined
  locals) and byte checks use `tr`, never `sed 's/\r$//'`.

WHY
  On J21 the implementer's `rustfmt --check` and an independent reviewer's
  PASS were both false evidence: the merge produced 12 `E0425` errors from
  identifiers that had lost a trailing `r`. In this batch the hardened review
  caught Python's nine E0308 wrong-argument sites by source inspection, and
  the orchestrator's real gate then caught six E0597 iterator-temporary
  errors that no source audit had claimed to rule out. The rule is L11: a
  syntax/format check is NOT a correctness check.

SOURCE
  `docs/ethics/lessons.md:27`, `:226-252` — L11 incident and rule;

DECISION 5 — Registration deferred to one separate reviewed job
---------------------------------------------------------------
LOCKED ANSWER [agent decision]
  The Python and Go adapter worktrees own only their module files, contract
  docs and fixtures. They record the exact registry edits they need but make
  none. One later orchestrator-delegated job (J26) applies both registrations
  in the shared files: manifests, `lib.rs`, `adapter.rs`, core default globs.

WHY
  Two worktrees editing `adapter.rs` or `Cargo.toml` at the same time would
  overwrite each other. Deferring registration also keeps the adapter
  packages reviewable on their own and lets a single gate verify the combined
  wiring. The Python fixture's `"py"` sentinel assertion in `adapter.rs:124`
  was a known blocker that only the registration job could retire.

SOURCE

DECISION 6 — Module named `golang` because `go` is a Rust keyword
-----------------------------------------------------------------
LOCKED ANSWER [agent decision]
  Directory and module are `crates/fnscope-parser/src/golang/`. The public
  type stays `GoAdapter`; the registry id and extension stay `"go"`/`"go"`.
  The internal module name never leaks into the manifest.

WHY
  `go` is a reserved Rust keyword and cannot be a module identifier. Renaming
  the public id would break the stable suffix contract and the manifest
  schema, so only the internal module name changes.

SOURCE
  `crates/fnscope-parser/src/golang/mod.rs:3-6` — "The directory is named
  `golang` because `go` is a Rust keyword and cannot be used as a module
  identifier"; `:37-45` — `id()` `"go"`, `extensions()` `&["go"]`.
  `docs/contract/adapters/go.md:12-15` — same rule and stable id.
  `docs/STATUS.md:145` — suffix `.go`, module `golang`, id `go`.

ALIGNMENT
  Iteration 16's zero-core-change invariant: the language is a plugin module;
  the user-visible contract keeps the natural `"go"` name.


DECISION 7 — No `.h` suffix is claimed
--------------------------------------
LOCKED ANSWER [agent decision]
  `PythonAdapter::extensions()` is `&["py"]` and
  `GoAdapter::extensions()` is `&["go"]`. Neither adapter claims a header or
  declaration-file suffix; Python and Go have no C-style header language,
  and the project's header rule (from the C adapter) is to avoid duplicate
  declarations.

WHY
  Claiming a declaration-only suffix would index the same callable twice with
  different ids and pollute the bidirectional call graph. Suffixes are stored
  without a leading dot and are lowercased by `Registry::for_extension`, so
  `"py"` and `"go"` already resolve `.py`, `PY`, `.go` and `GO`.

SOURCE
  `crates/fnscope-parser/src/python/mod.rs:40-43` — bare `py`, with the
  registry trim comment; `docs/contract/adapters/go.md:22` — bare `go`,
  case-insensitive resolution; `docs/contract/adapters/c.md:23-27` —
  "Header files are not claimed", with the duplicate-id rationale;
  `docs/STATUS.md:137-153` — the complete suffix -> adapter table names no
  header suffix for any language.

ALIGNMENT
  Avoids duplicate ids and dangling edges, supporting iteration 16 evidence
  (3) "a mixed polyglot fixture scans correctly in one manifest".
