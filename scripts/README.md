# Test and smoke harness

All scripts resolve the repository root from `repo-root.sh`, so they work from any working directory. Run them from Windows through WSL Debian with a placeholder for your clone path, for example `wsl.exe -d Debian --exec bash -lc 'cd /path/to/fnscope && bash scripts/test-all.sh'`. None of these scripts should be run while agents are still writing crate files; the orchestrator runs the gates once the workspace is stable.

`repo-root.sh` is the tiny path helper: executed directly it prints the absolute repository root, and sourced by the other scripts it publishes `REPO_ROOT`. It proves that no committed script contains a drive letter, user directory or absolute repo path. Run it with `bash scripts/repo-root.sh`.

`check-manifest.mjs` is the shared JSON validator. Given a manifest path it checks the tool and schema version, a non-empty function list with unique non-empty ids, well-formed `sha256:<64 hex>` AST hashes, unique `step-N` ids inside each function, resolvable `calledBy[].fnId` and `steps[].callsFnId` references, and non-empty `filePath`, `module`, `sourceCode` and `line >= 1` on every function. It prints `MANIFEST_OK: <N> functions, <E> call edges` on success or `MANIFEST_FAIL: ...` for every problem and exits non-zero. Run it with `node scripts/check-manifest.mjs path/to/fn-graph.json`.

`scan-fixture.sh` proves the scanner produces meaningful evidence from `tests/fixtures/sample_app`: at least eight functions, no leaked test or generated sources, `evaluateGrammarRole` called by `gradeSentenceExercise`, resolvable downstream calls, a `TOKEN_NOT_FOUND` / 422 error, and `dispatchWebhookEvent` marked `side-effect` with `net:outbound` plus a `secrets:read:` permission. It takes an optional output directory (default `/tmp/fnscope-e2e-<pid>`), cleans it up with a trap, and prints `FIXTURE_SCAN_OK` only when every assertion passes. Run it with `bash scripts/scan-fixture.sh`.

`smoke-server.sh` proves the whole HTTP surface works from the real CLI: it starts `fnscope open` detached on a tracked PID with a log in a unique `/tmp/fnscope-smoke-<pid>` directory, polls `/api/health` in a separate bounded loop (40 attempts, 0.25s apart), then checks `/`, `/app.js`, `/app.css`, `/api/fn-graph.json` and a `POST /api/invoke` trace response. The server is always stopped by tracked PID (never `pkill -f`) and its temp artifacts are removed before the script prints `SERVER_SMOKE_OK`. Run it with `bash scripts/smoke-server.sh [port]` (default port 4311).

`test-all.sh` is the single orchestrator gate. It runs `cargo fmt --all -- --check`, `cargo test --workspace`, `cargo build --release -p fnscope`, then the fixture scan and the server smoke test as separate steps, so no server is ever started inside the cargo test step. Every wait is bounded, and `ALL_TESTS_OK` is printed only after all five stages pass. Run it with `bash scripts/test-all.sh`.
